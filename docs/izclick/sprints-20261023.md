# IZCLICK: observaciones del 23/10/2026

## Sprint 1: fallos operativos

Base de interfaz: `izclick/clickup-native-list-detail-20261014` (PR #4). Se mantiene separada de `preview`, que no contiene la interfaz personalizada. No se supone que esta rama sea idéntica al código desplegado.

- **Fecha de evento:** el crawler de enlaces reemplazaba todo `IssueLink.metadata`, eliminando `izclick_kind` y `izclick_event_date`. No se encolan vistas previas de enlaces de producción. El worker también los protege ante trabajos ya encolados; comprueba la URL antes/después de la consulta y combina los metadatos de otros enlaces bajo bloqueo de fila. La ficha invalida la caché de Lista/Tabla y comprueba la fecha devuelta antes de confirmar el guardado.
- **Subtareas:** se filtran solo las filas raíz de Lista y Tabla. El renderizado anidado, los IDs, las relaciones y la paginación permanecen en sus stores originales. Las subtareas no reaparecen como independientes aunque estén en otro estado o página. Las listas de selección masiva usan los mismos IDs raíz visibles.
- **Adjuntos:** se abre una ventana accesible desde la celda de Tabla y una columna Adjuntos en Lista. Se consulta la lista al abrir, con carga, vacío, error y reintento. Se muestran nombres/tamaños, vista previa de imágenes/PDF y descarga por las rutas autenticadas de activos de Plane. Otros formatos se descargan para abrirlos en su aplicación.

### Validación antes de producción

1. Pruebas Node de jerarquía, formatos y anchos; pruebas Django de tareas encoladas, metadata y CRUD de fecha con PostgreSQL aislado.
2. Compilación Web y TypeScript. Prueba DOM del componente real de adjuntos (`qa/sprint1-attachments-dom.mjs`), con servicio/contexto simulados: selección de vistas previas, rutas de descarga, propagación del clic, vacío/error/reintento y cierre. No sustituye el QA visual ni la verificación con archivos reales.
3. QA autenticado: cambiar fecha en Lista/Tabla/ficha, recargar y comprobar calendario después de ejecutar el worker; crear/expandir subtareas; abrir/descargar adjuntos con editor y lector; denegación con usuario sin acceso. Revisar 1366 y 1920 px.
4. Confirmar API actualmente desplegada. PR #7 documenta que la API de correos carece de funciones personalizadas que el frontend consume; la rama de este sprint no sustituye esa reparación ni autoriza desplegar una API antigua sobre ella.
5. Integrar el cambio del crawler en **worker y API** compatibles con la versión real de producción. Cambiar solamente Web no corrige la pérdida de fecha. No se requieren migraciones de esquema nuevas para este sprint. Los metadatos ya perdidos no se reconstruyen inventando fechas.
